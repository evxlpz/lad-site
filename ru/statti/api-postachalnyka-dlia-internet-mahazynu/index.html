API поставщика: остатки, цены и статусы в 1С

Если у поставщика есть API, часть ежедневной рутины можно отдать учету: звонки «есть ли в наличии», письма с прайсами, сверку подтверждений. Но API у поставщиков очень разные: один отдает только «есть/нет», другой показывает остатки по складам, цены и статус каждого заказа. Разбираем, какие данные обычно доступны, где типичные ловушки и что выяснить до начала интеграции.

Коротко

Какие данные можно автоматически брать из API поставщика в 1С: остатки, цены, подтверждения и статусы заказов, что спросить у поставщика и как проверить обмен.

01API поставщика: что это и чем оно лучше прайса на почту

API — это машинный канал. Через него ваша 1С сама запрашивает у системы поставщика нужные данные и получает ответ в структурированном виде. Никому не нужно открывать письмо и переносить цифры: программа делает запрос и раскладывает ответ по полям. Прайс в Excel отражает состояние на момент выгрузки, а ответ API — на момент запроса.

Для магазина это значит меньше ручного переноса и меньше ошибок в цифрах. Но API — только дверь, а что за ней, решает поставщик. Поэтому до планирования автоматизации стоит посмотреть его документацию: какие данные он отдает, в каком виде и можно ли через API не только читать данные, но и отправлять заказы.

02Остатки: количество, «есть/нет» и склады

Остатки поставщики отдают чаще всего. Форматов несколько: точное количество, градации вроде «много / мало / нет» или простой признак наличия. Некоторые показывают остатки отдельно по каждому складу, иногда вместе с ожидаемой датой поступления.

Типичная ловушка — считать остаток поставщика гарантированным. Между вашим запросом и отгрузкой товар может купить другой клиент, а часть склада может быть уже в резерве. Поэтому стоит уточнить, что именно показывает API — свободный остаток или общий, и заложить запас: например, не считать товар доступным, если у поставщика остались единичные штуки.

Вторая ловушка — склады. Если поставщик отгружает из разных городов, срок доставки до вас будет разным. Какие склады учитывать, а какие нет, лучше решить до запуска, а не после первого заказа, который «застрял» на дальнем складе.

03Цены: закупочные, рекомендованные, валюта

Через API поставщик может отдавать вашу закупочную цену, рекомендованную розничную, акционные цены. Важно выяснить, учитывает ли ответ ваши персональные условия: часто API показывает базовую цену, а скидка появляется уже в счете.

Не менее важны валюта, НДС и единица измерения. Цена может быть в иностранной валюте, с НДС или без него, за штуку или за упаковку. Если не учесть это при настройке, в 1С появятся цены, которые формально «пришли автоматически», но не совпадают со счетом. На первых обновлениях сверяйте несколько позиций вручную.

Отдельный вопрос — что делать при изменении цены: молча обновить закупочную или показать изменение менеджеру, чтобы он пересмотрел розничную. Автоматика ускоряет работу, но ответственности за наценку не снимает.

04Заказы и статусы: подтверждение, частичное выполнение, отгрузка

Вторая половина обмена работает в обратную сторону: ваш заказ уходит поставщику, а он отвечает. Самое полезное, что может вернуть API, — подтверждение: что принято, в каком количестве, по какой цене. Дальше могут приходить статусы — собрано, отгружено, отменено, а у некоторых поставщиков еще и номер отправления или документа.

Частичное подтверждение — главная причина, по которой приходные накладные не сходятся с заказом. Вы заказали несколько позиций, поставщик подтвердил не все, и разница потерялась в переписке. Если ответ попадает в учет, расхождение видно сразу, еще до того, как товар пообещали покупателю.

Статусы поставщика редко совпадают с вашими. При настройке их нужно сопоставить: какие его состояния означают «принято», какие — «отказ», и что делать с новым неизвестным статусом, чтобы он не пропал незаметно.

05Что спросить у поставщика до начала интеграции

Несколько вопросов, которые экономят время: есть ли документация и тестовый доступ; как выдается ключ доступа и можно ли получить отдельный ключ для 1С; есть ли ограничения на количество запросов; по какому идентификатору искать товар — артикул, штрихкод или внутренний код поставщика; принимает ли API заказы или позволяет только читать данные.

Стоит также узнать, кто со стороны поставщика отвечает за API и предупреждают ли там об изменениях. Если формат ответа поменяют без предупреждения, обмен остановится, и лучше заранее знать, к кому обращаться.

Отдельная тема — соответствие товаров. Ваша номенклатура и каталог поставщика почти никогда не совпадают один в один: другие названия, артикулы с префиксами, другие единицы. Без сопоставления остатки и цены просто не к чему привязать.

06Как проверить, что обмен действительно работает

В первые дни после запуска сравнивайте данные в 1С с кабинетом поставщика на нескольких товарах: остаток, цену, статус свежего заказа. Сделайте пробный заказ и проследите, вернулось ли подтверждение и совпадают ли количества.

Дальше — ошибки. API бывает недоступен, ключ перестает действовать, товар исчезает из каталога. Важно, чтобы каждая неудачная попытка оставляла след, который виден без программиста: что отправлено, что вернулось, на чем остановилось. Иначе обмен «работает», пока кто-нибудь не заметит, что остатки давно не обновлялись.

И еще: решите, что показывает учет, когда связи с поставщиком нет, — последние известные данные или ноль. Это решение лучше принять осознанно, чем узнать о нем от покупателя.

Можно работать с его файлами в Excel, CSV или XML. Сначала оцениваем, стоит ли автоматизировать именно этого поставщика.
