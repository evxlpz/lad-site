Обмін Bitrix з 1С: типовий обмін чи власне API

Типовий обмін сайту з 1С закриває базові речі: каталог, залишки, замовлення. Але коли потрібні свої статуси, інтеграція з ботом, CRM чи кількома системами, він починає обростати костилями. Розберемо, де межа.

Що дає типовий обмін

Він передає товари, ціни, залишки та замовлення в стандартному вигляді. Для невеликого магазину без нестандартних процесів цього часто достатньо.

Де він починає заважати

Складнощі з’являються, коли потрібні нестандартні статуси замовлення, часткові відвантаження, кілька способів оплати зі своєю логікою, обмін з постачальником або дані для бота. Кожна така річ ламає типову схему.

Що таке власний обмін через API

Це серверна частина на сайті та розширення в 1С, які розмовляють між собою за вашими правилами: що і коли передавати, як оновлювати статуси, що робити з помилками. Додатково з’являється API, яким можна користуватися з бота чи CRM.

Журнал і помилки

У будь-якому обміні важливо бачити, що саме і коли пройшло. Журнал обміну з помилками економить години, коли замовлення «не доїхало».

Як ми робимо

Модуль «Хаб обміну» передає замовлення з сайту в 1С, повертає статуси на сайт, синхронізує клієнтів і дає власне API. Для Bitrix він готовий, під Laravel та інші платформи адаптується.

Часті питання

Чи можна залишити типовий обмін і додати лише API?

Так, залежить від задач. Спершу розбираємо, що саме болить, і лише потім вирішуємо, чи потрібна заміна.

Чи працює з Laravel?

Так, серверну частину адаптую під Laravel або іншу платформу.
